# 0005. События через PostgreSQL и поток по билету

**Контекст.** Статус заявки должен меняться у клиента и сотрудника без перезагрузки (SSE). Рассылка из памяти одного процесса не работает за балансировщиком. EventSource не умеет передавать заголовки, поэтому токен доступа приходилось класть в адрес, а адреса попадают в журналы.

**Решение.** Событие публикуется через `pg_notify`, каждый экземпляр API слушает канал и раздаёт событие своим потокам; при потере соединения экземпляр доставляет события локально и переподключается. Поток открывается по билету из `POST /events/ticket`: билет открывает только поток и живёт 30 секунд, токен доступа в адресе не принимается, nginx пишет в журнал путь без строки запроса. Конвейер берёт заявку под `pg_try_advisory_lock`, чтобы внешние источники опрашивались один раз.

**Отвергли.** Отдельный брокер (Redis, Kafka): ещё один сервис в запуске одной командой ради нагрузки, которой у прототипа нет. httpOnly-cookie вместо билета: правильнее, но требует CSRF-защиты всего API — оставлено следующим шагом.

**Цена.** Полезная нагрузка уведомления ограничена 8 КБ (события маленькие), доставка «не более одного раза»: интерфейс перечитывает данные при переподключении. Подробно: [architecture.md](../architecture.md#масштабирование-и-эксплуатация).
