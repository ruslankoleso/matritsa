# Как «Матрица» оценивает риск: формулы и допущения

Этот документ отвечает на три вопроса: **какая логика стоит за оценкой**, **по каким формулам считается каждый шаг** и **что в модели честно не доказано**. Код: `internal/scoring`, `internal/decision`, `internal/products`.

## Коротко

Модель разделяет три разных вопроса, которые в первой версии были перемешаны:

| Вопрос | Что отвечает | От чего зависит |
|---|---|---|
| **Кто этот заёмщик?** | Баллы, класс риска A–E, вероятность дефолта PD | Только от заёмщика: возраст бизнеса, выручка, текущие долги, кредитная история, просрочки, отрасль |
| **Что потеряет банк, если заёмщик не заплатит?** | Ожидаемые потери EL = PD × LGD × EAD | От класса заёмщика, срока, суммы и продукта |
| **Потянет ли бизнес эту заявку?** | Нагрузка на выручку, предельная сумма | От выручки, текущих платежей и параметров заявки |

> **Что было неправильно раньше.** В баллы входили факторы «нагрузка с учётом нового платежа» и «сумма к выручке». Из-за этого один и тот же заёмщик получал класс C на 2 млн ₽ и класс D на 20 млн ₽. Сумма заявки меняет доступность и потери, но не качество заёмщика, поэтому эти факторы убраны из оценки и вынесены в отдельные расчёты.

## Шаг 1. Баллы заёмщика (0–100)

Шесть факторов, которые не зависят от запроса. Каждый возвращает баллы и пояснение простыми словами.

| Фактор | Макс. | Как считается |
|---|---:|---|
| Возраст бизнеса | 15 | ≥ 36 мес. → 15; 12–35 → 10; 6–11 → 5; < 6 → 0 |
| Стабильность выручки | 20 | Коэффициент вариации помесячной выручки CV = σ / среднее: < 0,15 → 20; < 0,30 → 13; < 0,50 → 6; иначе 0. Меньше 3 месяцев данных → 0 |
| Текущая долговая нагрузка | 20 | Действующие платежи / средняя выручка: < 10 % → 20; < 20 % → 15; < 30 % → 9; < 45 % → 3; иначе 0 |
| Кредитная история (балл БКИ) | 25 | ≥ 750 → 25; 650–749 → 18; 550–649 → 9; < 550 → 0; истории нет → 10 |
| Просрочки | 15 | Нет → 15; до 30 дней → 8; 31–90 дней → 0 |
| Отрасль (группа риска ОКВЭД) | 5 | Группа 1 → 5; 2 → 3; 3 → 0 |

**Класс риска:** A ≥ 80, B 65–79, C 50–64, D 35–49, E < 35.

**Жёсткие стопы** (отказ независимо от баллов): компания не действующая по реестру; признак банкротства; просрочка в БКИ более 90 дней; нет подтверждённой выручки (тогда класс принудительно E).

## Шаг 2. Вероятность дефолта (PD)

Каждому классу соответствует годовая вероятность дефолта:

| Класс | A | B | C | D | E |
|---|---:|---:|---:|---:|---:|
| PD за год | 1 % | 3 % | 6 % | 12 % | 25 % |

Чем длиннее срок, тем выше вероятность, что дефолт случится хотя бы раз. Накопленная вероятность за срок кредита в месяцах `n`:

```
PD_срок = 1 − (1 − PD_год) ^ (n / 12)
```

## Шаг 3. Ожидаемые потери (EL)

Базовая формула кредитного риска, на которой строятся подходы IRB (Базель) и ожидаемые кредитные убытки по МСФО 9:

```
EL = PD_срок × LGD × EAD
```

| Параметр | Что это | Как задан в прототипе |
|---|---|---|
| **PD** | Вероятность дефолта | Из таблицы выше, пересчитана на срок кредита |
| **LGD** | Доля суммы, которую банк теряет при дефолте | Зависит от продукта: оборудование **40 %** (есть актив, который можно реализовать), оборотные средства **60 %**, овердрафт **65 %**, экспресс-кредит **75 %** (без обеспечения) |
| **EAD** | Сумма под риском на момент дефолта | Запрошенная сумма. Упрощение: не учитываем постепенное погашение, поэтому оценка консервативна |

## Шаг 4. Цена риска: надбавка к ставке

Базовая ставка продукта уже рассчитана на заёмщика класса A. Для остальных классов добавляется годовая ожидаемая потеря сверх уровня A:

```
надбавка (б.п.) = (PD_год(класс) − PD_год(A)) × LGD × 10 000
ставка          = базовая ставка продукта + надбавка
```

Для оборотных средств (LGD 0,6): A +0, B +120, C +300, D +660 б.п. Класс E предложения не получает.

## Шаг 5. Доступность: потянет ли бизнес платёж

Платёж по аннуитетной схеме (месячная ставка `r = ставка / 12`, срок `n` месяцев, сумма `S`):

```
платёж = S × r / (1 − (1 + r)^(−n))
```

Нагрузка и предельная сумма:

```
нагрузка = (действующие платежи + платёж по заявке) / средняя месячная выручка       должна быть ≤ 35 %
макс. сумма = (0,35 × выручка − действующие платежи) × (1 − (1 + r)^(−n)) / r
```

Именно этот шаг, а не класс риска, превращает слишком большую заявку в **встречное предложение** на меньшую сумму.

## Шаг 5а. Опыт погашения кредитов

Хорошая история в бюро подтверждается не только баллом, но и **суммой уже погашенных кредитов**. Бюро отдаёт число закрытых кредитов и сумму, погашенную полностью. Покрытие считается от запрошенной суммы:

```
покрытие = погашено ранее / запрошенная сумма
```

Автоматическое решение возможно, только если покрытие не ниже порога (по умолчанию **50 %**, `MinRepaidCoverage` в `internal/scoring/config.go`). Покрытие проверяется рядом с запросом и **не входит в баллы**: класс заёмщика остаётся оценкой самого заёмщика и не зависит от суммы заявки. Если покрытие ниже порога, заявка идёт к сотруднику с причиной «недостаточный опыт погашения кредитов», а у каждой заявки на рассмотрении этот показатель выводится в заключении как подсказка.

## Шаг 6. Решение

| Условие | Результат |
|---|---|
| Жёсткий стоп, класс E, либо предельная сумма меньше минимума продукта | Отказ с причинами |
| Класс A, сумма не выше лимита автоматического решения и не выше предельной, покрытие погашенными кредитами не ниже порога | Автоматическое предложение |
| Остальное (классы A–D) | Сотрудник банка; система рекомендует сумму = min(запрошенная, предельная, максимум продукта), округлённую вниз до 10 000 ₽ |

Решение принимает человек или правило, а не ИИ. ИИ только пересказывает эти цифры простыми словами.

## Пример на одних и тех же данных

ИП Кузнецова Е. С. (класс **B**, 70 баллов, PD 3 %), продукт «Кредит на оборудование» (LGD 40 %):

| | 2 млн ₽, 30 мес. | 20 млн ₽, 40 мес. |
|---|---:|---:|
| Класс риска | B | B |
| PD за срок | 7,3 % | 9,7 % |
| EL = PD × LGD × EAD | ≈ 58 400 ₽ | ≈ 773 600 ₽ |
| Нагрузка с новым платежом | 24 % | 117 % |
| Предельная сумма по нагрузке | ≈ 3,7 млн ₽ | ≈ 4,6 млн ₽ |
| Итог | Сотрудник, рекомендация 2 млн ₽ | Сотрудник, рекомендация ≈ 4,6 млн ₽ вместо 20 |

Класс остаётся тем же. Большая заявка стоит банку больше (EL выше в 13 раз) и не помещается в платёжеспособность бизнеса, поэтому она уходит на встречные условия, а не «ухудшает» заёмщика.

## На что опирается модель и чем она не является

**Опирается на общепринятые идеи:**
- разложение кредитного риска на PD, LGD и EAD и формулу EL = PD × LGD × EAD (внутренние рейтинги Базеля, ожидаемые убытки МСФО 9);
- балльные скоринговые карты: факторы заёмщика дают баллы, баллы сводятся в класс;
- проверку доступности платежа по доле платежей в выручке (аналог DTI/PTI).

**Не является:**
- откалиброванной статистической моделью. У прототипа нет исторических данных о дефолтах, поэтому **пороги баллов, таблица PD и значения LGD иллюстративные**. Они подобраны так, чтобы логика была объяснимой и монотонной (хуже заёмщик, дольше срок, больше сумма, меньше обеспечения → больше потери и дороже ставка), но не подтверждены данными;
- регуляторным расчётом достаточности капитала. Формулы коэффициентов риска и RWA здесь не используются: они нужны банку для капитала на портфель, а не для решения по одной заявке.

**Что нужно для боевой модели:** выгрузка истории кредитов и дефолтов по МСП; подбор факторов и весов (логистическая регрессия или градиентный бустинг); калибровка PD по классам; оценка LGD по фактическим взысканиям и залогам; валидация (Gini/KS, стабильность во времени); мониторинг дрейфа.

## Где менять параметры

| Что | Файл |
|---|---|
| Максимумы баллов, таблица PD, предел нагрузки 35 %, порог просрочки | `internal/scoring/config.go` |
| Пороги внутри факторов | `internal/scoring/scoring.go` |

Тесты, закрепляющие поведение: `internal/scoring/scoring_test.go` (в том числе «класс не зависит от суммы заявки» и «длиннее срок и больше сумма → больше EL»), `internal/seed/scenarios_test.go` (демо-компании дают задуманные исходы и не меняют класс от размера заявки).
